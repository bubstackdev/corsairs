# BF16 ABI and validation

The installed macOS 27 CoreAIRuntime interface declares `NDArray.ScalarType.bfloat16` separately from `.float16`. [BFloat16Reference.swift](../experiments/swift/BFloat16Reference.swift) independently compiles that case, an NDArray constructor and a scalar-type comparison. Its retained [IR](evidence/v0.2-bfloat16/bfloat16.ll), [SIL](evidence/v0.2-bfloat16/bfloat16.sil) and [ARM64 assembly](evidence/v0.2-bfloat16/bfloat16.s) are pinned with the SDK by the [compiler manifest](evidence/v0.2-bfloat16/compiler-build.json).

The compiler loads the external `i32` case-tag constant `$s13CoreAIRuntime7NDArrayV10ScalarTypeO8bfloat16yA2EmFWC`, obtains complete ScalarType metadata and invokes its destructive enum-tag injection witness, VWT slot 13. Float16 uses the distinct `...O7float16yA2EmFWC` constant. Corsairs resolves the BF16 symbol and uses these same witnesses; it does not encode a guessed ordinal or reuse the Float16 tag. `NativeDType::Bf16` has two-byte storage and participates in native descriptor tag recognition. Owned arrays, retained tensors, mutable states and Metal unsafe-buffer construction all use this centralized native dtype/case/width path.

Public `BFloat16::from_bits`/`to_bits` preserve every encoding. Widening to f32 preserves all bits by shifting into the high 16 bits. Narrowing uses round-to-nearest, ties-to-even for finite values. Numerical NaNs preserve the sign and representable high payload/signaling bits; an otherwise discarded-only payload becomes one, keeping the value a NaN. This policy is independent of a reference library's NaN quieting/canonicalization. Raw native storage must preserve NaN payloads exactly; arithmetic through NaNs is a different contract.

The independent [conversion differential](evidence/v0.2-bfloat16-conversion.json) passed debug and release against pinned NumPy 2.3.5 and `ml_dtypes` 0.6.0. It covers 1,392,227 distinct f32 encodings: 1,388,149 finite/infinity values matched exact narrow and widened bits; 4,078 NaNs passed separate class, sign and documented payload checks. The corpus includes every BF16 representable, all finite BF16 midpoint neighborhoods with their adjacent f32 encodings, exponent boundaries and one million seeded random inputs. There were 4,044 NaN payload differences from the numerical reference, recorded separately from failures. This is a broad deterministic differential, not all 2³² f32 encodings. [The checker](../scripts/check_bfloat16.py) retains corpus/output vectors and hashes under `target/bfloat16-conversion` and never imports Core AI.

[Small fixtures](../fixtures/parity-v02/bfloat16/manifest.json) cover finite x+x, scalar and empty shapes, changing dynamic shapes, a stride-sensitive transpose, and three repeated named-state updates. They use pinned b3 authoring, including the same explicit private handle-authoring seam as the earlier state fixture; production execution uses Core AI's public native APIs. Their [retained manifest](evidence/v0.2-bfloat16/fixtures-manifest.json) pins the six-case asset set. A separate raw input contains all 65,536 BF16 encodings, including both zero signs, infinities and every NaN payload. This input is only copied, never used as an arithmetic expectation.

The independent [Swift executable](../experiments/swift/BFloat16RunReference.swift) passed its [final six-case native observation](evidence/v0.2-bf16-swift-final-native.json), exit 0 with complete coverage. It verified raw all-encoding identity and BF16/Float16 distinction, then executed every fixture with CPU-only and GPU-preferred options. Its [retained results](evidence/v0.2-bfloat16/swift-output/swift-results.json) and sibling byte files contain 22 output records, including changing shapes and repeated state. The earlier [five-case observation](evidence/v0.2-bfloat16-swift-native.json) remains historical evidence; the six-case fixture manifest supersedes it.

The [safe Rust probe](../experiments/rust/bfloat16_parity.rs) passed both [debug](evidence/v0.2-bfloat16/check-debug.json) and [release](evidence/v0.2-bfloat16/check-release.json) differential checks. Each completed 46 configurations and matched 104 output/state values exactly against independently saved Swift bytes. Coverage includes owned arrays, retained native tensors, Metal automatic/fixed output bindings, scalar/empty inputs, dynamic shapes, three repeated state updates and exact native output metadata. Both profiles also preserved all 65,536 raw encodings through native and Metal upload/download, exercised clone/drop lifetimes, completed native/Metal chains in both compute modes, and submitted 20 iterations of abandoned success/error requests before the final drain. Their [debug](evidence/v0.2-bfloat16/native-debug.json) and [release](evidence/v0.2-bfloat16/native-release.json) observations exited 0 with complete coverage. The [build/check script](../scripts/check_bfloat16_native.py) compiles or checks captured results; it never executes a native probe itself.

The separate [final core check](evidence/v0.2/final-core/checks.json) passed on the same production source. Its [build manifest](evidence/v0.2/final-core/build-manifest.json) and check report contain 114 matching current source hashes and source identity `3ff97ad3492669e0f790c75e9e675228c8f6a9598d64e9e0b4fff6e075eaf4a5`. [Transitive drain semantics](runtime-drain.md) are backed by the [final native lifecycle run](evidence/v0.2-drain-lifecycle-final-native.json): all five lifecycle tests passed. The BF16 abandoned-job probe establishes completion, while native store-count checks belong to those separate lifecycle tests.

CPU/GPU settings are preferences; these fixtures do not identify an actual delegated backend, establish arbitrary operator coverage or make a performance claim. Scalar native strides were `[]`, empty strides were `[0,0]`, and the transpose result materialized with contiguous `[2,1]` strides on both preferences. Thus this transpose gate does not independently establish a noncontiguous BF16 runtime output. Downloads still use the shared checked nonnegative-stride packer; negative strides remain unsupported. Dynamic Metal outputs use automatic allocation and explicit mutable bindings require fixed shapes. The one-GiB per-tensor cap is unchanged. These small exact fixtures do not replace the separate original-weight H3 block/schedule/backbone acceptance gates, and raw NaN payload preservation does not specify NaN arithmetic results.
