# v0.1 safe/unsafe boundary review

Reviewed 2026-10-15 for Apple Silicon macOS 27; native validation host: macOS 27.0.1 arm64.

**Conclusion:** no unresolved substantive ownership, lifetime, or ABI defect was found in the reviewed release subset. This is a scoped source and contract review, conditional on the recorded native ABI, rather than a proof of memory safety or an external audit. The reviewer also implemented `native/owned.rs` and contributed compiler-reference research. No production source was modified for this report.

## Boundary conclusions

- **Thread confinement:** the worker constructs, uses, and destroys the `!Send` native session on its own thread. Requests and results contain owned Rust data and integer handles. Native addresses do not cross the public channel. The default public API keeps native modules private; enabling `abi-research` exposes explicitly unsafe research operations.
- **Handle and request lifetime:** pending model/function/run jobs retain their parent handles and input/state storage. Functions retain their model. Final function release is queued before model release. Dropping a `Task` does not cancel or free its queued/running request. Session destruction explicitly clears functions, then models, before unloading its framework handle.
- **Failure and wake handling:** completion guards resolve requests on channel failure and Rust worker panic. Results are published under a mutex and wakers run outside it. The final `Task::wait` change polls first, then returns `ReentrantWait` for a pending wait on its own worker. A ready result remains readable there, and a rejected wait leaves the submitted request owned by the queue. The focused `reentrant_waker_cannot_block_its_worker` unit passed in the integration run; its implementation and test were inspected here.
- **Native storage:** allocations follow complete runtime metadata and VWT stride/alignment. Initialization is tracked independently from allocation. Optional payload moves use the payload witnesses; associated descriptor projection uses the enum witnesses before moving the matching payload. Consumed values are marked uninitialized, preventing double destruction. Array modification uses compiler-established generic metadata, scratch storage, and coroutine resumption.
- **Calls and completion:** inline assembly declares ordinary call clobbers and Swift-specific registers, without false memory/stack restrictions. Throwing synchronous calls use x21; throwing async resumes use x20. The custom async completion calls the original native finalizer before publishing completion, preloads data before the root can be freed, and preserves its saved registers/stack. Separate callback/waiter `Arc` references protect completion state. The caller task reference survives until completion; the concurrency image remains process-pinned for executor epilogues.
- **Views and errors:** underlying input/state buffers outlive their dependent views and the native call. Mutable views are consumed only after a started call completes. Returned bytes are copied before view/value destruction, with checked shape, dtype, stride, pointer, and byte count. Empty tensors skip zero-length pointer copies. Error projections and cached type names remain borrowed; names are copied and each owned native error is released through RAII, including fallible reflection paths.
- **Validation:** names, shapes, scalar types, byte lengths, boolean encodings, and resource limits are checked before tensor construction. Scalar and empty tensors are supported. Unsupported descriptor kinds, unresolved dimensions, scalar types, and noncontiguous nonempty outputs return typed errors. Typed tensor access uses scalar byte conversion rather than unaligned pointer casts.

## Evidence and limits

[Debug](v0.1/checks-debug.json) and [release](v0.1/checks-release.json) each passed 32 positive backend cases, 16 negative cases, 40,000 stateless/stateful inference calls, and repeated load/drop/abandoned-request lifecycle checks. Both final reports and the [build manifest](v0.1/build-manifest.json) record source identity `dff0fc8ebf7cfd38eda61a9fc4425bbb9eadb0bd9fa0961d4cd6a6a5cca707ab`. Their complete 32-entry source maps agree, and every hash, including all 27 Rust source entries, was verified against the current files after the final documentation-comment corrections. No production behavior changed in those corrections. [Native dropped-future coverage](v0.1-native-drop-counts.json) separately exercised return to zero model/function handles. [Float16 differential validation](v0.1-float16-conversion.json) matched NumPy for 1,382,598 finite/infinite inputs in both profiles; NaN payload equality was deliberately excluded.

These checks do not prove leak freedom, arbitrary-model correctness, or safety on another OS/SDK/architecture. The supported five scalar types, fixed resolved descriptors, contiguous Rust-owned tensors, and named state are the reviewed subset. GPU preference does not establish which device executed a call. Native traps, allocation aborts, framework bugs, hangs, and hostile model parsing are not contained by Rust panic handling. Cancellation, arbitrary Swift closures/executors, image/Metal storage, and future ABI changes require separate work and evidence.

## Coordinator follow-up

After final validation, the coordinator read the complete production `native/owned.rs`, `native/async_task.rs`, `native/arm64.rs`, `native/metadata.rs`, `native/errors.rs`, `native/text.rs`, `native/loader.rs`, `native/task_create.rs`, and `native/mod.rs`, together with the public worker, facade, and sealed scalar encoding boundary. This includes a second review of the owned backend by a different contributor from its implementer. The checks covered allocation/initialization flags, consuming calls on error, Optional and descriptor projection, early-return destruction order, mutable-view lifetimes, worker confinement, completion-reference ownership, call clobbers, and framework lifetime. No additional substantive defect was found and no production changes resulted. The review has the same ABI and arbitrary-model limitations stated above.
