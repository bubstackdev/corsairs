# Corsairs v0.1 release contract

Accepted on 2026-10-15: deliver a safe, useful Rust inference library for existing `.aimodel` assets, with verified Python parity for the bounded subset below. The work ends at a concrete release candidate ready to publish; uploading a crate or reserving a registry name is a separate action. Full runtime and authoring parity remains the longer-term project objective.

## Required scope

| Area | v0.1 commitment |
| --- | --- |
| Platform | Apple Silicon and macOS 27, with explicit tested OS and toolchain versions |
| Models | Load assets, enumerate functions, inspect input/output/state descriptors |
| Tensors | Owned, contiguous float16, float32, int32, int64, and bool tensors; checked shapes and typed access |
| Execution | Named inputs and outputs, repeated inference, named state tensors |
| Compute | CPU-only and GPU-preferred specialization, compared against identical Python settings |
| Rust API | Safe public interface, typed errors, async loading and execution; dropping a future retains native resources through completion |
| Distribution | Usable library crate, examples, API documentation, and a diagnostic CLI |

The following features are deferred: graph authoring, custom Metal kernels, image/pixel buffers, packed low-bit formats, shared GPU storage, profiling callbacks, explicit Neural Engine control, and native cancellation. Dropping a future is supported resource management, not a promise to cancel its native operation.

The implemented v0.1 value boundary is resolved static tensor signatures, rank at most 64, and at most 1 GiB per tensor. Scalar and empty tensors are supported; empty tensors also have a nonzero-dimension size guard. Native inputs and completed outputs/state are copied into contiguous owned storage. The default native module is private; `abi-research` exposes unsafe development probes. Calls on one runtime share one serialized worker.

## Package preparation

The packaging design is one public `corsairs` library with the ABI implementation as a private native module. Research-only access is behind an `abi-research` feature; ordinary consumers use the safe facade. This avoids a dependency on a separately unpublished ABI package. Do not treat a successful workspace build as proof that the distributable package builds. Any additional published internal dependencies must have resolvable version requirements when their dependent crate is packaged.

The public package sets `corsairs`, version `0.1.0`, a precise description, a packaged README, tested `rust-version`, and the chosen `MIT OR Apache-2.0` license. Research executables remain unpublished. Package source, examples, and their small model assets; generated compiler outputs and broad research evidence remain outside the library package. Inspect the actual archive rather than relying on an exclusion pattern. Cargo's manifest reference describes [registry metadata and file inclusion](https://doc.rust-lang.org/cargo/reference/manifest.html). Local packaging can warn about metadata that the registry rejects: the [crates.io publish implementation](https://github.com/rust-lang/crates.io/blob/main/src/controllers/krate/publish.rs) requires a nonempty description and either license field. A public repository URL is optional; omit it while no real URL exists.

Once the final manifests and package names exist, run these commands separately for each package, in dependency order:

```sh
cargo package -p corsairs --list
cargo package -p corsairs --locked
cargo publish -p corsairs --dry-run --locked
```

Build API documentation on the supported target with `cargo doc --workspace --no-deps`. For hosted docs, set `[package.metadata.docs.rs]` with `default-target = "aarch64-apple-darwin"` and `targets = []`. The [docs.rs metadata reference](https://docs.rs/about/metadata) documents these settings; its default target is otherwise Linux. A metadata setting does not replace verifying that the documentation actually builds.

Also run `cargo test -p corsairs --no-default-features` and `cargo doc -p corsairs --no-default-features --no-deps`. Workspace builds enable `abi-research` through the lab; they do not independently validate the ordinary dependency's feature boundary.

`cargo package` verifies an extracted archive; `cargo publish --dry-run` performs packaging verification without uploading it. Neither command reserves a crate name. Verify package consumers and examples using the extracted archive as well. Do not use `--no-verify` to turn an unresolved dependency or native build failure into a passing release gate. See Cargo's [publishing workflow](https://doc.rust-lang.org/cargo/reference/publishing.html) and [`cargo publish` command reference](https://doc.rust-lang.org/cargo/commands/cargo-publish.html).

The genuine crates.io dry-run is currently unavailable because this environment cannot resolve its index host. Adding `--offline` does not repair it in Cargo 1.99: [HTTP handle setup rejects offline mode](https://github.com/rust-lang/cargo/blob/5f94df4789f005f9a352888e8355ffc645b7ed0e/src/util/network/http.rs#L61-L68), including the [client initialization](https://github.com/rust-lang/cargo/blob/5f94df4789f005f9a352888e8355ffc645b7ed0e/src/context/mod.rs#L1818-L1823) used by registry commands. The error can therefore precede an actual API request even with cached index configuration.

An [isolated local rehearsal](evidence/v0.1/local-publish-rehearsal.json) passed the real `cargo publish --dry-run --locked` command against a local `file://` Git index, using a temporary Cargo home/target directory and an inert `.invalid` API URL. Cargo packaged 39 files, compiled the extracted crate, prepared publish metadata, and stopped at its [explicit dry-run branch](https://github.com/rust-lang/cargo/blob/5f94df4789f005f9a352888e8355ffc645b7ed0e/src/ops/registry/cargo_publish.rs#L611-L628). No verification bypass, real registry connection, credential, or upload was involved. This establishes the local package/publish-preparation path; it does not establish crates.io name availability, authentication, or server acceptance.

Before an actual upload, run the genuine crates.io dry-run in a connected environment, recheck registry name availability, and select the publishing account. `corsairs` availability remains unverified because crates.io and its API/index could not be fetched from this environment. These are pre-upload actions, not substitutes for or blockers to local release-candidate verification. No name has been reserved and no registry credentials have been read or changed. A public repository URL and registry ownership setup are not additional local release gates.

## Release candidate

All local release-candidate gates pass. The bounded API, exact b3 comparisons, 80,000 stress inferences, error/recovery paths, native cleanup, binary16 conversion, scoped review, measured benchmarks, extracted-package consumers, and local publish rehearsal are retained.

The candidate is [dist/corsairs-0.1.0.crate](../dist/corsairs-0.1.0.crate): 39 files, 57,533 compressed bytes, SHA-256 `2d9d4e0f3d827b6dbb7b03a9ce0285c9e33d2ffd0e1dfcffe5cfd6fd9215cf5f`. The local dry-run archive is byte-for-byte identical. The preparation notes above record the state before the maintainer completed publication.
