# BF16 acceptance for MiniMax H3

The original 128-row H3 block, all 50 retained base-schedule pairs, and the full synthetic 50-block backbone **pass** through the safe owned Rust API against exact saved Swift/Core AI results. The backbone passes both across a verified checkpoint and in one runtime with transitive drain between its two graph segments. The additions requested locally as `corsairs-v0.3-h3.md` are being included in the unpublished v0.2 development work.

The [pinned safe driver](evidence/v0.2-h3/backbone-staged/driver.rs) creates one runtime, acquires one graph at a time, retains the BF16 result as owned host bytes, drops the function, and waits on `Runtime::drain()` before loading the next graph. Its [independent verification](evidence/v0.2-h3/backbone-staged/independent-verification.json) checks the event order: segment0 completion, segment0 drain completion, segment1 load, segment1 completion, segment1 drain completion, exact final output. This demonstrates the within-process handoff; drain does not promise immediate OS eviction of weight/compiler pages.

The single-runtime run took 88.564456 seconds after runtime initialization: segment0 load 25.816034 seconds and inference 19.865015 seconds; segment1 load 20.637519 seconds and inference 21.540805 seconds. The separate checkpoint runs took 37.000766 and 220.944937 seconds, with child RSS high-water counters of 56,973,574,144 and 48,440,475,648 bytes respectively. These are instrumented acceptance observations with varying cache state, not paired performance measurements. RSS is Darwin `RUSAGE_CHILDREN`, including preparation helpers; it is not separately measured Metal allocation and must not be added to Metal accounting. These results do not establish conditioner co-residency on a 64 GB host.

## Reproduction

Prepare the isolated default-feature build without inference, then coordinate native gates sequentially:

```sh
python3 -B scripts/check_h3.py --mode block128
python3 -B scripts/check_h3.py --native --no-build --mode block128 --timeout 240 \
  --output /private/tmp/corsairs-h3-block128
python3 -B scripts/check_h3.py --native --no-build --mode schedule50 --timeout 240 \
  --output /private/tmp/corsairs-h3-schedule50
python3 -B scripts/check_h3.py --native --no-build --mode backbone --timeout 270 \
  --output /private/tmp/corsairs-h3-backbone-staged
python3 -B scripts/check_h3.py --native --no-build --mode backbone-stage0 --timeout 240 \
  --output /private/tmp/corsairs-h3-backbone-stage0
python3 -B scripts/check_h3.py --native --no-build --mode backbone-stage1 --timeout 240 \
  --resume /private/tmp/corsairs-h3-backbone-stage0/checkpoint.json \
  --output /private/tmp/corsairs-h3-backbone-stage1
```

Full asset/input hashing occurs outside the native-child deadline. A cold 25-block function may take substantial preparation time; coordinate the outer observation window accordingly. Source/binary/library changes reject `--no-build` and checkpoint resume. Live events, stderr, and large output/checkpoint bytes stay outside source trees. Build/check reports initially live under `target/h3-check` until retained as evidence; native runs also save their report beside the outputs. H3 Cargo artifacts are isolated under `target/h3-check/cargo`. Existing Krea evidence and compiled baselines are preserved.

## Bounds

These are synthetic hidden states and original BF16/F32 transformer blocks. The local lab has no complete H3 generation bundle or decoded audio/video trajectory oracle. Conditioning/vision export contracts, actual multimodal packing, text refinement, input/output heads, source schedules and latent updates, VAEs, keyframes, and media mux remain application/forge work. Conditioner co-residency and full generation on a 64 GB host have not been tested. The bounded gate adds no H3-specific sampler, low-bit kernel, authoring API, global tensor-cap increase, or end-to-end generation claim.
