# Corsairs v0.2 validation and publication

The candidate is `corsairs 0.2.0` for Apple Silicon on the recorded macOS 27.0.1
host, with Rust 1.99 and Xcode/SDK 27. It was published on 2026-10-15. Reports identify
tested source bytes and binaries independently of the repository commit.
All validation gates below pass. Committing and pushing prepares the repository;
tagging and publication are recorded below.

## Changes from v0.1

- Dynamic tensor descriptors and concrete-call validation, plus per-model
  compute and frequent-reshape options.
- Retained native tensor handles for chaining without a Rust host byte round
  trip, checked nonnegative-stride downloads, and conservative mutable-alias
  rejection.
- Persistent shared Metal buffers, explicit output/state bindings, and unsafe
  application queue/buffer interoperability with documented ownership and
  synchronization contracts. Calls currently fence individually.
- Same-runtime model and function batches that join every started invocation
  before cleanup, including errors and abandoned tasks. Function batches require
  distinct model handles.
- Distinct `BFloat16` storage and conversions throughout owned, native and Metal
  tensor paths. Raw storage preserves all 65,536 encodings.
- `Runtime::drain()` for preceding requests and their transitive release
  cascades, preserving externally held resources and excluding later independent
  submissions. It makes no OS/cache eviction promise.

The limits remain rank 64 and 1 GiB per tensor, including checked shape/stride
arithmetic. Full Python API parity, model authoring, images, packed low-bit
public tensors, cancellation, and pipelined encoded submissions are outside this
release. Application-specific schedules, tokenization, kernels, asset selection
and residency policy remain application responsibilities.

## Packaging and performance

One public package contains the safe facade and private native implementation;
there are no dependencies or unpublished internal package requirements. Default
features are empty; `abi-research` is explicit development-only access. Metadata
declares Rust 1.99, the repository, packaged README, and `MIT OR Apache-2.0` with
both full license texts. The research workspace executable remains unpublished.

The pre-commit candidate is [`dist/v0.2.0/pre-commit/corsairs-0.2.0.crate`](../dist/v0.2.0/pre-commit/corsairs-0.2.0.crate):
**52 files, 95,666 bytes**, SHA-256
`4d3cf3ce0895cff49f624132d558117a914d5407e0cf07a66fcf21607aa4dec3`.
Independent verification confirms every archive member/hash, identical target
and distribution archives, and byte equality with all 49 corresponding current
source files. The three Cargo-generated files are separately hash-checked; the
normalized manifest and lock contain only this package, no dependencies, and
empty default features.

This archive records the pre-commit validation candidate. Packaging the final
release after committing can update Cargo's VCS metadata and therefore the
archive hash without changing the validated Rust source.

The [benchmark record](benchmarks.md) retains three alternating owned/native
generation pairs and three serial/batch preparation pairs. Warm-cache preparation
medians were 1.759 seconds serial and 0.755 seconds batch on that build; batch
loading used a higher child RSS high-water counter in every pair. These are
small, same-host observations with uncontrolled system/cache state, not a
general speed or memory guarantee. The tiny v0.1 workload was slower than Python.

## Publication

On 2026-10-15, `v0.2.0` was tagged at commit
`e46d421932602f3e117cdce65056ca782e9f55e2` and published to
[crates.io](https://crates.io/crates/corsairs/0.2.0) and
[GitHub Releases](https://github.com/bubstackdev/corsairs/releases/tag/v0.2.0).
The clean-commit package passed Cargo verification. Its only changed member
relative to the tested pre-commit archive is `.cargo_vcs_info.json`.

The [published archive](../dist/v0.2.0/corsairs-0.2.0.crate) is 95,658 bytes with
SHA-256 `5cb0757cfcb9098ae1bf2a54f63c7cf063696dd64a7e26730ccb915b8ebfc17e`.
An independent registry download and the registry's checksum match that archive.
A fresh default-feature consumer downloaded `=0.2.0` through Cargo and passed
native tensor chaining with unsafe code forbidden.
[Publication provenance](evidence/v0.2/publication.json),
[registry consumer](evidence/v0.2/registry-consumer.json), and
[native run](evidence/v0.2/registry-consumer-untraced-native.json) retain the details.

The normal connected Cargo dry run was blocked by this session's DNS restriction
and is not counted as passing. The authorized upload used the documented Cargo
Registry Web API through the permitted HTTP client; the stored publishing
credential was not logged. The server accepted it without warnings. The original
candidate/archive evidence remains preserved separately.
