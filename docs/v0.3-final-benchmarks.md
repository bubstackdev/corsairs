# Final v0.3 benchmark checks

Recorded 2026-10-15 on the same macOS 27.0.1 arm64 host. These are current-source release checks; historical measurements remain unchanged.

## Matched tiny Rust/Python calls

The unchanged feedforward asset takes Float32 `[2,3]` and returns `[2,2]`. Each phase used 10 warmups and 100 measured sequential calls. There was one descriptive Rust/Python pair per compute setting: Rust then Python for CPU, Python then Rust for GPU preferred. The reference is `coreai-core 1.0.0b3` on CPython 3.12.14. Default reshape settings were preserved.

| Setting | Phase | Rust median, µs | Python median, µs |
| --- | --- | ---: | ---: |
| CPU | `owned_run` | 33.062 | 76.4375 |
| CPU | `native_run_download` | 19.292 | 43.0415 |
| GPU preferred | `owned_run` | 444.937 | 493.9165 |
| GPU preferred | `native_run_download` | 361.9375 | 427.354 |

`owned_run` includes copying the input data/map, constructing native inputs, submitting and waiting, and returning all output bytes. `native_run_download` reuses prepared native inputs and includes map cloning, submission/wait, and downloading every output. Model/function loading, exact validation, output destruction, and diagnostic cleanup/drain are outside each measured interval. Rust uses its public worker API; Python uses its public binding and event loop. These are matched application boundaries, not identical internal execution paths or isolated kernel timings.

All eight language/setting/phase results report exact output bytes on every iteration, matching the same names, dtypes, shapes, and model/input/golden identities. All four processes exited 0, were joined, and stayed within their deadlines. The [final native observation](evidence/v0.3-final/smallbench-final-native.json) also exited 0 with only `SIGSTOP` listed. Raw samples and complete boundaries are in the [CPU pair](evidence/v0.3-final/benchmarks/feedforward-cpu.json), [GPU pair](evidence/v0.3-final/benchmarks/feedforward-gpu-preferred.json), and [checks](evidence/v0.3-final/benchmarks/checks.json).

One pair does not establish a repeated-pair distribution, stable clocks, a general speedup, or full-render performance. No cache purge was performed. Earlier before/after cache evidence remains in [v0.3-symbol-cache.md](v0.3-symbol-cache.md); these final results also include the current stream-completion implementation and must not be treated as a fresh isolated cache A/B test.

## Current H3 and Krea checks

The final H3 functional block uses BF16 hidden `[1,19333,5376]`, its retained functional weights and mixed BF16/Float32/Int32 inputs, GPU preferred, one warmup and three samples. Rust's median was **544.279459 ms** for retained native run plus every output download, and **565.763833 ms** for persistent Metal input/fixed-output encode plus fence/readiness and every output download. All iterations matched the full expected output bytes. This is one H3 block, not an H3 video generation; there was no fresh Python H3 arm in this final check. See [h3.json](evidence/v0.3-final/h3.json).

The final Krea `metal-chain --parallel-loads` check completed the fixed 768×1344, eight-step provided-text fixture in a recorded generation interval of **19.433270208 s**. All **13** Swift-reference hashes matched: three first-segment carries, eight step latents, final latents, and decoded Float32 CHW pixels. It used one persistent queue, 32 encode calls, eight reused output buffers, CPU Float32 Euler, and the owned dynamic decoder. Four model loads and four function loads each reached peak in-flight 4 and joined with zero active tasks.

That Krea interval begins after denoiser loading and includes Metal setup, inference, readbacks, CPU Euler, hashes/file writes, decoder loading, and cleanup. Denoiser preparation was separately 1.904534583 s. Text came from the saved fixture; tokenization and text encoding are outside this mode. It is an instrumented correctness run, without a paired Python generation or a performance-distribution claim. See the retained [Krea checks](evidence/v0.3-final/krea-checks.json), [native observation](evidence/v0.3-final/krea-native.json), and [build receipt](evidence/v0.3-final/krea-build.json).
