# Larger tensors for H3

v0.3 development raises the checked per-tensor storage boundary from 1 GiB to
4 GiB. The requested H3 hidden and RGB shapes fit within that boundary. Rank
remains limited to 64; scalar/empty behavior, dtype/rank/fixed-dimension checks,
nonzero-dimension guards and checked stride/span arithmetic remain enforced.
The published v0.2.0 remains at 1 GiB.

| Capacity fixture | Type | Shape | Bytes |
| --- | --- | --- | --- |
| Long-profile hidden | BF16 | `[1, 102816, 5376]` | 1,105,477,632 |
| Short-profile RGB | float32 | `[124, 1344, 768, 3]` | 1,535,901,696 |
| Long-profile RGB | float32 | `[345, 1344, 768, 3]` | 4,273,274,880 |
| Exact storage limit | float32 | `[1073741824]` | 4,294,967,296 |

The boundary is shared by host tensor construction, native input/output
validation, retained downloads, strided extents and Metal tensor views. Native
input validation now reuses the host shape arithmetic, including the empty
tensor guard. Contiguous retained/Metal downloads use a single checked byte copy;
noncontiguous nonnegative strides retain the checked packing path. A transpose,
padded view or broadcast cannot use the contiguous shortcut.

## Qualification

v0.3 is not published. CPU capacity gates pass. The final quiet-host GPU window
passes hidden, short RGB and the exact 4 GiB flat case. Long RGB fails in the
independent Swift oracle before Rust executes; this shape is not GPU-qualified.
The reference assets are tiny `x+x` graphs with large signatures, authored using
the pinned b3 wheel. They contain no H3 weights or large constant payloads.

An independent Swift executable and a safe Rust probe generate offset-varying
finite nonzero patterns in 1 MiB blocks. Seeds vary modulo 251, so a wrapped/truncated address at
1, 2 or 4 GiB cannot silently match a repeated prefix. Every output byte is
compared; SHA-256 binds the Rust results to the independent Swift execution.
The current Swift oracle immediately copies all output bytes before comparing
them, matching Rust's immediate owned readback. A slow scan of live native
storage can conceal late writes. [The harness revision](evidence/v0.3-large-tensors/immediate-snapshot-revision.json)
preserves identical production sources and Rust executables.

Each pass checks seven paths. The [earlier pattern-v2 reports](evidence/v0.3-large-tensors/before-immediate-snapshot/README.md)
retain their exact Swift/Rust build identities. The current immediate-snapshot
[exact-limit CPU report](evidence/v0.3-large-tensors/immediate-snapshot/limit-f32-cpu-release.json)
also passes all seven paths. The [debug BF16 CPU report](evidence/v0.3-large-tensors/immediate-snapshot/h3-hidden-cpu-debug.json)
passes the same paths. These observations do not establish performance guarantees.

The separate [raw storage gate](evidence/v0.3-large-tensors/raw-storage/checks.json)
passes exact 4 GiB native upload/download for bool, float16, bfloat16, float32,
int32 and int64, including every-byte checks and full hashes. It covers the bool
dimension `2^32`, two-byte dimensions `2^31`, six maximal empty shapes and twelve
typed oversized-empty rejections before runtime construction. It executes no
models, inference or Metal queues. The [Metal extent probe](evidence/v0.3-large-tensors/metal-extents-native.json)
separately passes a 4 GiB backing buffer with views at 1 GiB, 2 GiB and its final
16 bytes, six invalid extent/alignment requests, and downloads after dropping
the original backing/export owners and draining.

Each case runs independently under CPU-only and GPU-preferred specialization.
The Rust probe covers owned inference, retained upload/download and chaining,
Metal explicit output bindings and automatic-output chaining, and abandoned
native/Metal requests followed by drain and input-content checks. Native work
runs serially; large payloads remain outside the repository and are not saved.
The exact-limit case tests a byte count of `2^32` without truncation.

Nonallocating tests cover all public scalar widths, limit/limit-plus-one,
rank/overflow, oversized empty shapes, and strided spans extending to the shared
limit. Focused layout tests distinguish contiguous data from transpose, padding,
broadcast and unit axes with arbitrary strides. Metal uses the same size guard.
Workspace unit tests, strict all-target/all-feature clippy, formatting and rustdoc
pass. The current [debug/release dynamic-shape, handle-lifetime, native and Metal
parity regressions](evidence/v0.3-large-tensors/regressions/v02-checks.json) pass.
The [H3 BF16 block gate](evidence/v0.3-large-tensors/regressions/h3-checks.json)
matches live, cached and modulation Swift hashes. The [Krea eight-step native
chain](evidence/v0.3-large-tensors/regressions/krea-checks.json) matches all three
first carries, eight latent steps, final latents and decoded pixels. Generated
fixture-reference manifests needed fresh driver builds; failed preflight identities
are retained separately and no stale driver was accepted.
[Matched Python performance results](v0.3-benchmarks.md) are recorded separately.

## Investigated failures

The first BF16 CPU capacity pattern included negative zero. Its Swift oracle
returned positive zero for `-0 + -0`, so the mathematical-bit expectation failed
before Rust ran. The [original signed-zero evidence](evidence/v0.3-large-tensors/initial-signed-zero/README.md)
is retained. Capacity pattern v2 uses finite nonzero values; all comparisons
remain exact. This capacity test does not replace the existing numerical edge
fixtures or raw BF16 bit-preservation gates.

The 4,273,274,880-byte RGB GPU case produced partial Rust outputs with zero tails.
Native upload/download was exact, but successive retained output snapshots
differed. An independent Swift immediate-copy reproduction also failed, and its
dictionary variant terminated with SIGSEGV. A separately fenced Metal explicit
binding matched every output byte; automatic chaining then reported native GPU
timeouts and exceeded the process deadline. These are failed observations,
not passing qualification. [Diagnostic sources/results](evidence/v0.3-large-tensors/diagnostic-sources/manifest.json)
and the [SDK/compiler/native contract audit](evidence/v0.3-large-tensors/view-contracts/README.md)
are retained. The audit found full-width counts and shared synchronization code
for both Swift run overloads; it found no additional public NDArray host-wait API.

An independent Aether H3 generation was running during the original diagnostic
window. After the user freed the GPU, the quiet-host retry still failed in Swift
with `byte mismatch at block 3160`, before Rust ran. The Swift process exited
with status 1, without a trap or timeout. Contention alone therefore does not
explain this failure. Neither a slow scan, sleep nor tolerance change was added
as a production workaround. A definitive framework cause, general GPU limit,
or successful long-RGB GPU result is not established. The flat 4 GiB pass does
not qualify every tensor shape; CPU success must not be advertised as GPU acceptance.

Successful per-tensor allocation does not promise that a complete graph fits.
