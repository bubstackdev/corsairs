# Corsairs v0.3.0

v0.3 adds checked storage and CPU execution up to 4 GiB per tensor, a qualified
2 GiB GPU-preferred inference boundary, and per-library native symbol caching.
It retains v0.2 dynamic signatures, BF16, retained native tensors, Metal bindings,
concurrent independent model/function loading, and transitive cleanup draining.

Stateless owned/native GPU calls now use one private persistent ComputeStream
and Metal command queue per runtime. Native arrays retain storage across
chaining. Readiness errors and result owners stay alive through the actual queue
completion fence, including abandoned futures. The private queue remains until
runtime destruction; draining releases unreferenced request/result handles.

## Supported bounds

`MAX_TENSOR_BYTES` is 4 GiB and `MAX_GPU_INFERENCE_TENSOR_BYTES` is 2 GiB.
The GPU check covers both logical payload and referenced strided storage span.
An imported Metal tensor view is bounded relative to its origin; its offset and
extent must separately fit the backing allocation. A larger backing allocation
does not make a small valid view oversized.

Fixed signatures and concrete inputs/bindings are checked before GPU dispatch.
Dynamic result shapes/spans are checked after fenced readiness, before host
copying or public handle publication. This accepted-value policy cannot bound
unknown intermediates, working memory, allocation or execution time. An oversized
dynamic result may execute before rejection. Applications remain responsible for
memory admission and asset residency. GPU preference permits native fallback.

Stateful owned/native GPU calls retain a fixed input/state/output signature
envelope of 1 GiB. CPU-only execution and explicit Metal state bindings are
alternatives. Rank 64, overflow, empty-tensor nonzero-dimension guards, fixed
dimensions, names, dtypes, negative-stride rejection and alias checks remain.

from historical diagnostics. The [symbol-cache experiment](v0.3-symbol-cache.md)
records three alternating before/after pairs: tiny CPU owned-call medians fall
from about 1.18 ms to 34 µs. [Matched Python comparisons](v0.3-benchmarks.md)

(32 configurations) and Metal parity (64 configurations); BF16 parity

repeated abandoned native requests and three abandoned Metal requests in each
case. GPU cases cover hidden, RGB124, RGB173 and exact 2 GiB. CPU cases cover
hidden, RGB124, RGB345 and exact 4 GiB. Raw native storage roundtrips every byte
at 4 GiB for all six scalar types. Nineteen boundary checks include eleven typed
GPU rejections and eight exact empty results; raw storage remains independent
of inference policy.

## Known exclusion

The 4,273,274,880-byte RGB GPU fixture is not qualified. Ordinary Swift immediate
snapshots failed; a persistent-stream repair produced exact owned/native/chained
results but still timed out during abandoned-call qualification. v0.3 rejects
its fixed GPU signature before inference. This is a conservative support policy,
not a discovered universal Core AI or hardware limit. CPU capacity success and
flat 4 GiB diagnostic passes do not qualify arbitrary GPU shapes or full H3
generation. Application-level H3 generation timing/residency remains separate.

A CPU-only empty broadcast `[0,1] -> [0,536870913]` faults with SIGBUS inside
ordinary Swift `function.run(inputs:)`, before output metadata or snapshots,
without Rust/Corsairs linkage. [Independent reproduction](evidence/v0.3-final/empty-broadcast-diagnostic/finding.md)
retains the exact graph, stage markers and signal. This graph is excluded from
CPU qualification; empty x+x boundary cases still pass. The internal cause and
behavior of other empty broadcasts are not established. Its fixed oversized
GPU descriptor is rejected before inference.
