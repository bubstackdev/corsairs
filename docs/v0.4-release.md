# Corsairs v0.4.0

v0.4 adds request cancellation, Neural Engine preference, read-only asset
inspection and seven scalar types. It retains every v0.3 bound, path and
known exclusion.

## Changes from v0.3.1

- **Queued-request cancellation.** `Task::cancel_handle()` returns a
  `CancelHandle`. `cancel()` prevents a request that has not reached Core AI
  (`Cancel::Prevented`, and the task resolves to `Error::Cancelled`) or reports
  `Cancel::TooLate`. Core AI has no cancellation path for running work; see the
  [investigation](cancellation.md). Dropping a task still detaches.
- **Neural Engine preference.** `Compute::NeuralEnginePreferred` and the CLI's
  `--compute neural-engine-preferred`. Every preference still permits CPU, GPU
  and Neural Engine, so all non-CPU preferences share the qualified GPU stream
  and bounds ([compute units](compute-units.md)).
- **Asset inspection.** `Runtime::inspect_asset(path, statistics)` returns
  metadata, declared functions and optional operation and storage statistics
  without loading a model. `Runtime::device_architecture()` returns the device
  architecture name, and `corsairs inspect` prints both
  ([asset metadata](asset-metadata.md)).
- **Scalar types.** `f64`, `i8`, `i16`, `u8`, `u16`, `u32` and `u64` tensors
  ([scalar types](scalar-types.md)). On the Neural Engine, int8/uint8 overflow
  saturates and int16 values beyond ±2048 can be rounded.
- **New errors:** `Error::Cancelled` and `Error::InvalidAsset`.

### Breaking changes

`Compute` and `DType` are now `#[non_exhaustive]`, so exhaustive `match`
expressions on them need a wildcard arm. The new public structs (`AssetInfo`
and related types) are also `#[non_exhaustive]`.

## Release gates

Recorded on macOS 27.0.1 (26A434) with Rust 1.99.0:

- `cargo fmt --all --check`, `cargo clippy --offline --workspace --all-targets --all-features -- -D warnings`, and rustdoc with `-D warnings`
- `cargo test --offline -p corsairs --no-default-features -- --include-ignored`:
  61 library tests, including 10 native tests, plus CLI and doctest; 18 Python reference tests
- `scripts/check_v01.py --native --cycles 10000 --loads 100 --dropped 100`:
  151 positive and 24 typed negative public-API configurations across three
  backends, plus 10,000 stateless and 10,000 stateful calls, 100 load/drop cycles
  and 100 abandoned futures of each kind per backend, in debug and release
- `scripts/check_v02.py --native`: native-handle parity 151/151 and Metal parity
  302/302, plus dynamic-shape and handle drivers, in debug and release
- BF16 driver: 46 configurations, 104 exact values and all 65,536 raw encodings
  through native and Metal storage in each profile
  ([summary](evidence/v0.4/bf16-native.json)). This reran the Rust driver
  against the fixtures; the v0.3 Swift oracle comparison was not repeated.
- Large tensors against the independent Swift reference, release profile: the
  exact 2 GiB GPU-preferred boundary and the exact 4 GiB CPU boundary
  ([GPU](evidence/v0.3-large-tensors/v0.4-release/gpu-limit-f32-gpu-preferred-release.json),
  [CPU](evidence/v0.3-large-tensors/v0.4-release/limit-f32-cpu-release.json))
- `scripts/check_package_v03.py --native` (now accepting 0.3.x and 0.4.x):
  every archive member, extracted-package and isolated-consumer builds, eight
  native examples, and packaged CLI and BF16 checks
  ([candidate verification](evidence/v0.4/package-verification.json))

Not rerun for v0.4: the H3/Krea external-asset gates, the remaining large-tensor
shapes (RGB124/173/345 and hidden), GPU rejection boundaries, and benchmarks.
Those paths are unchanged apart from Neural Engine preference, which shares the
GPU path.
