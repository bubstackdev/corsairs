# Corsairs v0.4.1

v0.4.1 adds float8 tensors and fixes the findings of the `v0.3.1..v0.4.0`
code review. It is backwards compatible with v0.4.0: a v0.4.0 consumer,
including code that relies on `DType::ALL: [DType; 13]`, builds unchanged.

## Changes from v0.4.0

- **Float8 tensors.** `DType::{Float8E4M3Fn, Float8E5M2}` with the
  `Float8E4M3Fn` and `Float8E5M2` element types. Storage keeps every encoding;
  `to_f32` is exact; `from_f32` rounds to nearest, ties to even, and matches
  ml_dtypes, including overflow (NaN for E4M3FN, infinity for E5M2) and
  canonical signed NaN ([scalar types](scalar-types.md#float8)).
- **`DType::all()`** returns every supported type as a slice that later releases
  can extend. `DType::ALL` keeps its v0.4.0 contents (13 types, no float8) so
  its type does not change, and is deprecated.
- **`corsairs inspect`** reports pre-1970 asset creation dates as negative Unix
  seconds instead of `null`.
- **Verification pipeline.** `check_v01.py` pins each golden set's backends and
  success, reviewed-error and negative counts. It requires every case/backend
  pair exactly once and checks native errors against the reviewed list, so a
  shrunken or edited golden set can no longer pass the native gates. The float8
  conversion corpus now includes the exact max/overflow ties.

## Release gates

Recorded on macOS 27.0.1 (26A434) with Rust 1.99.0:

- `cargo fmt --all --check`, clippy with `-D warnings` and rustdoc with `-D warnings`
- `cargo test --offline -p corsairs --no-default-features -- --include-ignored`:
  62 library tests, including 10 native tests, plus CLI and doctest; 24 Python
  reference tests, including the new grid-shape regressions
- `scripts/check_v01.py --native --cycles 10000 --loads 100 --dropped 100`:
  181 positive and 24 typed negative public-API configurations across three
  backends with full stress, in debug and release
- `scripts/check_v02.py --native`: native-handle parity 181/181 and Metal parity
  362/362, plus dynamic-shape and handle drivers, in debug and release
- `scripts/check_float8.py`: all 256 encodings of each type and 1,002,151
  binary32 inputs against ml_dtypes 0.6.0, 0 mismatches in debug and release;
  the [report](evidence/v0.4/float8-conversion.json) hashes match the released source
- BF16 driver: 46 configurations, 104 exact values and all 65,536 raw encodings
  in each profile ([summary](evidence/v0.4.1/bf16-native.json))
- Large tensors against the independent Swift reference, release profile: exact
  2 GiB GPU-preferred and 4 GiB CPU boundaries
  ([GPU](evidence/v0.3-large-tensors/v0.4.1-release/gpu-limit-f32-gpu-preferred-release.json),
  [CPU](evidence/v0.3-large-tensors/v0.4.1-release/limit-f32-cpu-release.json))
- `scripts/check_package_v03.py --native`: every archive member,
  extracted-package and isolated-consumer builds, eight native examples, and
  packaged CLI and BF16 checks ([candidate verification](evidence/v0.4.1/package-verification.json))

As for v0.4.0, the H3/Krea external-asset gates, the other large-tensor shapes,
GPU rejection boundaries and benchmarks were not rerun.
